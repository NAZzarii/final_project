Пропоную створити "GameMatch" — Веб-платформу для пошуку тіммейтів та паті у відеоіграх (Discord / LFG аналог для ґеймерів).
  🛠️ Як це працюватиме "у формі прототипу"
База даних: Вся інформація (користувачі, ігри, лобі) зберігається локально в одному файлі app.db (SQLite).

"Тіммейти" та "Профілі": Користувачі реєструються через звичайну форму, а в профілі вручну вказують свій тег (наприклад, Discord: Nickname#1234 чи Telegram: @user).

"Чат і Зв'язок": Замість складного чату в реальному часі хост лобі просто залишає текстове посилання на свій Discord/канал, яке стає видимим тільки після того, як хост натисне «Прийняти заявку».

👥 Розподіл завдань (Максимально простий план на 4 людей)
1. Главний (Каркас проєкту + Авторизація + База)
Основа, на якій працюють інші 3 розробники.

Таск 1.1: Створити ASP.NET Core MVC проєкт, залити на GitHub і налаштувати .gitignore.

Таск 1.2: Підключити SQLite через Entity Framework Core (налаштувати DbContext і створити першу міграцію).

Таск 1.3: Налаштувати ASP.NET Core Identity (стандартний вхід, реєстрація, вихід).

Таск 1.4: Додати до стандартного користувача декілька полів в БД: DiscordTag, SteamLink, AboutMe.

2. Костя (Форма створення лобі + Список оголошень)
Основна бекенд-логіка для ігрових кімнат.

Таск 2.1: Створити модель Lobby (Гра, Опис, Скільки потрібно гравців, Мікрофон так/ні, Час гри).

Таск 2.2: Написати сторінку з формою «Створити лобі» (вибір гри з випадного списку, текстові поля).

Таск 2.3: Написати бекенд для Головної сторінки: виведення списку всіх відкритих лобі з БД.

Таск 2.4: Фільтрація лобі на головній сторінці за обраною грою (наприклад, фільтр: Тільки CS2 або Тільки Dota 2).

3. Нікіта (Верстка UI + Темний ґеймерський дизайн)
Візуальна частина, щоб проєкт виглядав сучасно та ефектно на демонстрації.

Таск 3.1: Підключити красиву темну Bootstrap-тему (наприклад, безкоштовний шаблон Darkly з Bootswatch) у _Layout.cshtml.

Таск 3.2: Заверстати картки лобі на головній сторінці: іконка гри, бейджики (Мікрофон 🎙️, Потрібно: 2/5), опис та кнопка «Детальніше / Подати заявку».

Таск 3.3: Заверстати профіль користувача та форму редагування своїх контактів (Discord / Telegram).

Таск 3.4: Заверстати сторінку перегляду конкретного лобі (список учасників та контакти).

4. Сергій (Логіка «Прийняти заявку» + Довідник ігор)
Взаємодія між користувачами та адміністрування.

Таск 4.1: Створити модель LobbyRequest (Заявка на вступ: Id, LobbyId, UserId, Status: Pending / Accepted / Rejected).

Таск 4.2: Логіка кнопки «Подати заявку» для гравця та кнопки «Прийняти» / «Відхилити» для творця лобі.

Таск 4.3: Показувати контакну інформацію (Discord / посилання) гравцю тільки тоді, коли його заявку прийнято.

Таск 4.4: Проста сторінка для Адміна: можливість додати нову гру в довідник (назва гри, картинка-логотип).

Порядок роботи. Нікіта й Сергій залежать від моделей Кості та Главного, тому спершу Главний робить каркас, Identity і міграцію та заливає на GitHub, а вже потім усі беруть гілки. Інакше будуть конфлікти міграцій. Краще, щоб міграції створював тільки один чоловік.
Модель Game. У плані вона є тільки в Сергія (4.4), а Костя вже в 2.2 потребує вибору гри. Тому Game (Id, Name, ImageUrl) краще зробити в самому початку і одразу засидити 4-5 ігор (CS2, Dota 2, Valorant, Minecraft…).
Зв'язок Lobby з автором. У Lobby треба HostId (користувач-творець), GameId і IsOpen. Без цього "прийняти заявку" не працюватиме.
Захист від дурниць у заявках.
Не можна подати заявку у своє лобі.
Не можна подати двічі.
Приймати/відхиляти може тільки хост (перевірка в контролері, не лише приховування кнопки).
Після набору потрібної кількості гравців лобі закривається (IsOpen = false).
Контакти. Показуємо Discord хоста лише тим, чия заявка Accepted (і самому хосту), перевірка на сервері.
Адмін. Простий варіант: роль “Admin” через seed одного акаунта, і сторінка додавання гри доступна тільки йому ([Authorize(Roles="Admin")]).
Бонус для красивого вигляду, якщо буде час. Сторінка "Мої лобі / Мої заявки" зі статусами кольоровими бейджами та повідомлення "Заявку прийнято" на головній.
